= K8S Installer
:github: https://github.com/ten1010-io/k8s-installer
:version: 1.0.0

== 개요

K8S Installer는 오프라인 환경에서 쿠버네티스 클러스터를 구성하는 도구입니다

노드 프로비저닝과 kubeadm 기반 클러스터 구성까지만 수행하며, CNI를 포함한 애드온 차트는 설치하지 않습니다.
클러스터 구성 후 CNI 플러그인은 직접 설치해야 노드가 Ready 상태가 됩니다.

== 사용법

K8S Installer는 제어 노드의 `/opt/k8s-installer`에 설치되며, 릴리스 단위로 관리됩니다.
설치된 릴리스는 `/opt/k8s-installer/release` 파일에 기록되고, 모든 관리 노드가 동일한 릴리스를 갖습니다.

플레이북은 제어 노드 자신을 건드리면 실행 중인 설치기를 무너뜨리므로 그 노드만 제외합니다.
제어 노드가 인벤토리의 어느 노드인지는 `inventory.yml`의 `control_node_ih`로 선언합니다.

[source,yaml]
----
control_node:
  hosts:
    localhost:
      ansible_connection: local
      control_node_ih: node1
----

선언이 실제로 플레이북을 실행하는 노드를 가리키지 않으면 모든 플레이북이 시작 단계에서 중단됩니다.

=== 클러스터 설치

[source,shell,subs="+attributes"]
----
git clone {github}.git
cd k8s-installer
git checkout v{version}
./download-bin.sh
sudo ./setup.sh

sudo /opt/k8s-installer/ansible/configure-control-node-ssh.sh   # 출력된 안내에 따라 모든 관리 노드에 SSH 설정

# /opt/k8s-installer/ansible/inventory.yml 과
# /opt/k8s-installer/ansible/group_vars/all/vars.yml 수정

source /opt/k8s-installer/venv/bin/activate
cd /opt/k8s-installer/ansible
ansible-playbook -i inventory.yml playbooks/setup-k8s-installer.yml
ansible-playbook -i inventory.yml playbooks/setup-cluster.yml
----

=== 설치기 업그레이드

[source,shell,subs="+attributes"]
----
git clone {github}.git
cd k8s-installer
git checkout v{version}          # 업그레이드할 릴리스 태그
./download-bin.sh
sudo ./upgrade.sh          # inventory.yml 과 vars.yml 은 보존되며, 새 릴리스의 파일은 *.new 로 남습니다

source /opt/k8s-installer/venv/bin/activate
cd /opt/k8s-installer/ansible
ansible-playbook -i inventory.yml playbooks/upgrade-k8s-installer.yml
----

NOTE: 클러스터 업그레이드(`upgrade-cluster.yml`)와 인증서 갱신(`renew-certs.yml`)은 아직 제공되지 않습니다.

=== 스냅샷 릴리스

`-SNAPSHOT` 으로 끝나는 버전은 개발용 빌드입니다. 같은 이름으로 내용이 계속 바뀌므로
두 노드가 같은 스냅샷을 보고해도 같은 것을 들고 있다고 볼 수 없고, 따라서 **업그레이드의
출발점이 될 수 없습니다.**

[cols="1,1,3"]
|===
|설치된 버전 |목표 버전 |판정

|릴리스 |릴리스 |`upgradable_from` 에 있으면 허용
|릴리스 |스냅샷 |허용. 릴리스를 내기 전 업그레이드 경로를 시험하는 용도
|스냅샷 |동일 스냅샷 |허용. 업그레이드가 아니라 **재배포**이며 개발 중 몇 번이든 가능
|스냅샷 |그 외 |**거부.** `reset.sh` 후 `setup.sh` 로 재구축
|===

릴리스를 낼 때는 `release.yml` 의 `version` 에서 `-SNAPSHOT` 을 떼고 커밋한 뒤 태그를 붙이고,
다음 개발 버전으로 다시 올립니다. 이 문서의 `:version:` 속성은 사용자가 체크아웃할 태그를 가리키므로
릴리스 버전까지만 올리고, 다음 개발 버전으로는 올리지 않습니다.

[source,shell]
----
# 개발 중        version: "1.1.0-SNAPSHOT"    태그 없음
# 릴리스         version: "1.1.0"   → commit → git tag v1.1.0
# 다음 개발      version: "1.2.0-SNAPSHOT"
----

=== 클러스터 제거

[source,shell]
----
source /opt/k8s-installer/venv/bin/activate
cd /opt/k8s-installer/ansible
ansible-playbook -i inventory.yml playbooks/reset-cluster.yml
ansible-playbook -i inventory.yml playbooks/reset-k8s-installer.yml
deactivate

sudo /opt/k8s-installer/ansible/reset-control-node-ssh.sh   # 출력된 안내에 따라 모든 관리 노드의 SSH 설정 제거
sudo /opt/k8s-installer/reset.sh
----
